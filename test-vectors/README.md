# Test vectors

Shared test data for the two public formats other services rely on. Any implementation outside
this repo (for example the .NET backend that builds links for moje.placanje.rs) should run these
cases instead of keeping its own copy of the expected values.

Generated by [`scripts/test-vectors.ts`](../scripts/test-vectors.ts); do not edit by hand.
`npm test` fails when a file no longer matches the code. After an intended format change, run
`npm run test-vectors:write` and commit the result.

## `v2-links.json` — payment links (`/s#2.<code>`)

The format is described on [placanje.rs/api](https://placanje.rs/api).

- `fieldOrder` — position of each field in the value array.
- `encode[]` — `slips` (every field present, defaults included) and the `payload` an encoder must
  compress: the JSON value before DEFLATE. Compare it as JSON, not as text. `fragment` is one valid
  encoding. Compressed bytes may differ between zlib implementations, so compare by decoding.
  A conforming implementation:
  1. builds exactly `payload` from `slips`;
  2. decodes `fragment` back to `slips`;
  3. decodes its own encoding back to `slips`.
- `decode[]` — fragments an encoder never produces but every decoder must accept: legacy v1 links
  and GZIP-compressed v2 links (Apps Script). Each must decode to `slips`.
- `invalid[]` — fragments that must decode to "no slips" (`null`), never to an error.

## `ips-qr.json` — NBS IPS QR string (`K:PR`)

`cases[]` — a slip's `data` and the QR string placanje.rs builds from it. `qr: null` means the slip
is not valid for a QR code.

Conventions these cases pin down:
- `paymentCode` is the code printed on the slip (e.g. `189`); `SF` in the QR is that code + 100.
- Payer fields are never written to the QR.
- Cyrillic is transliterated to Latin, and typographic characters and `|` are replaced.
- The receiver block (`N`) is cut to 70 characters and the purpose (`S`) to 35.
